# FPGA-Based Synchronous Consensus Accelerator

This is a hardware prototype implementation of a **Leaderless Deterministic Consensus Protocol** based on FPGA.

The project utilizes **PTP (IEEE 1588)** to provide nanosecond-level time synchronization, building a distributed consensus system based on **TDMA (Time Division Multiple Access)**. By completely **offloading** the consensus logic to the FPGA, it achieves microsecond-level low latency and high-throughput log ordering without CPU involvement in the core interaction process.

## 🚀 Getting Started

### Dependencies

This project uses an open-source toolchain for development and verification:

* **Icarus Verilog (iverilog):** Simulation compiler (Version >= 10.0, v11+ recommended)
* **GTKWave:** Waveform viewer
* **Make:** Build tool

### Running Simulation

1. **Clean previous builds:**

```bash
make clean

```

2. **Compile and run full system simulation:**
   The default target runs `tb_system_top.v`, simulating the interaction of 3 nodes in a synchronous network.

```bash
make run

```

*Expected Output:* The terminal will print the Commit Logs for each node at the end of every Slot, verifying that data from Nodes 0, 1, and 2 are strictly ordered.
3. **View Waveforms:**
After execution, open the generated waveform file using GTKWave:

```bash
gtkwave tb_system_top.vcd

```

## 🏗️ Architecture Design

### Core Concepts

* **Synchronous Assumption:** The network is assumed to be synchronous, meaning clock skew across all nodes is within the `GUARD_BAND`, and packet transmission latency has a deterministic upper bound.
* **TDMA Scheduling:** Time is divided into **Macro Slots** (e.g., 10us). Inside each Macro Slot, specific **Micro Slots** are assigned to different nodes as sending windows.
* **Raw Ethernet Protocol:** Uses a custom EtherType (`0x88B5`) to bypass the IP/UDP stack, maximizing bandwidth utilization.

### Module Data Flow

1. **Scheduler (`slot_scheduler.v`):** Monitors PTP time. It triggers `tx_trigger` when the local Micro Slot arrives and triggers `slot_end_pulse` when the Macro Slot ends.
2. **Generator (`packet_generator.v`):** Upon receiving a trigger, immediately assembles an Ethernet frame (containing SlotID, NodeID) and transmits it via AXI Stream.
3. **Parser (`packet_parser.v`):** Filters incoming traffic for `0x88B5` packets, extracts the Payload, and discards expired or erroneous packets.
4. **Core (`consensus_core.v`):**

* **Collect:** During the Slot, fills the internal Buffer with data received from various nodes.
* **Commit:** Upon receiving `slot_end_pulse`, freezes the Buffer and commits data to the Host DMA in a fixed order (`Node 0 -> 1 -> 2`).

## ⏱️ Protocol Configuration

Key parameters defined in `rtl` and `sim` (configurable):

| Parameter         | Default Value    | Description                               |
| ----------------- | ---------------- | ----------------------------------------- |
| `MACRO_SLOT_NS` | 10,000 ns (10us) | Duration of one complete consensus cycle  |
| `MICRO_SLOT_NS` | 1,000 ns (1us)   | Sending window duration for a single node |
| `GUARD_BAND_NS` | 100 ns           | Protection band against clock jitter      |
| `NODE_COUNT`    | 3                | Number of nodes in the cluster            |
| `ETHERNET_TYPE` | 16'h88B5         | Custom Ethernet Protocol ID               |
